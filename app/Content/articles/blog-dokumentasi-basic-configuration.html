Dalam home lab, dokumentasi berguna jika menjawab pertanyaan konkret: perangkat terhubung ke port mana, VLAN apa yang lewat, alamat diperoleh dari mana, dan jalur mana yang perlu diuji saat layanan gagal. Saya menyusun Basic Configuration dari sketsa pribadi, screenshot Cisco, backup MikroTik, serta pemeriksaan Debian.

Pisahkan sumber dan hasil pengamatan

Sketsa menjelaskan hubungan fisik ONT, MikroTik, Cisco, server, PC, dan access point. Screenshot Cisco membuktikan mode port, PVID, serta membership VLAN. Backup MikroTik memberi nama interface, gateway, pool DHCP, dan parameter WireGuard. SSH ke Debian mengonfirmasi IP, route, resolver, container, serta konfigurasi proxy yang aktif.

Catat perbedaan yang ditemukan

Catatan awal menyebut static IP melalui Winbox, sedangkan Debian menggunakan DHCP. Saya mempertahankan perbedaan ini sebagai catatan, bukan memaksakan narasi agar seluruh sumber terlihat sama. Hal serupa berlaku untuk Tailscale: penggunaan VPN diketahui dari informasi saya, tetapi node dan rutenya belum diperiksa.

Susun pemeriksaan mengikuti dependensi

Untuk masalah jaringan, mulai dari port dan VLAN, lalu IP, gateway, DNS, serta firewall. Untuk aplikasi, periksa akses SSH dan status container, kemudian origin, proxy, tunnel, dan domain. Urutan ini membuat setiap pemeriksaan memiliki tujuan yang jelas.

ip -brief address show ens18
ip route
cat /etc/resolv.conf
sudo dhcpcd -U ens18
ping -c 3 192.168.20.1
getent ahostsv4 azrilachdi.web.id
cd /mnt/data/docker-compose/portfolio/repository
sudo docker compose --env-file ../runtime.env ps
sudo docker compose --env-file ../runtime.env logs --tail=50 app

Tulis cuplikan yang dapat dipahami

Dokumentasi VLAN memuat cuplikan yang direkonstruksi dari parameter backup, bukan perintah restore siap jalan. Dokumen VPN memakai perintah pemeriksaan tanpa memublikasikan kunci. Angka performa, status keamanan, dan detail perangkat yang belum diperiksa tidak saya tambahkan hanya untuk membuat halaman terlihat lengkap.
