Saya memakai tiga VLAN di home lab: VLAN 10 untuk management, VLAN 20 untuk server, dan VLAN 30 untuk client. MikroTik mengatur gateway serta DHCP, sedangkan Cisco SF200-24 membagi koneksi ke port yang sesuai. Dengan susunan ini, saya lebih mudah membedakan perangkat pengelola jaringan, layanan server, dan perangkat client.

Trunk dari ether4 ke GE1

Di MikroTik, ketiga interface VLAN berada pada ether4. Port ini terhubung ke GE1 Cisco. GE1 membawa VLAN 10, 20, dan 30 sebagai tagged, sedangkan VLAN 1 tetap untagged dengan PVID 1. Jadi, satu kabel uplink membawa beberapa VLAN ke switch.

Pengaturan tag di kedua ujung uplink perlu cocok. Kalau interface VLAN di router sudah benar tetapi membership pada switch salah, client tetap bisa gagal mendapat alamat atau menghubungi gateway.

Membagi access port

FE1 dan FE2 memakai access VLAN 10. GE2 memakai access VLAN 20 untuk cabang server. FE3 memakai access VLAN 30 untuk cabang access point TP-Link dan client. FE4 sampai FE24 masih tercatat sebagai trunk dengan PVID 1; pembagian layanan saya fokuskan pada port di tabel ini.

DHCP untuk setiap segmen

Pool DHCP tiap VLAN dimulai dari .100 sampai .200 dengan lease 30 menit. Alamat gateway selalu .1 pada subnet masing-masing, dan DNS client diarahkan ke Technitium di 192.168.20.199. Saya mengecek interface VLAN, scope DHCP, dan lease ketika client tidak mendapat alamat yang sesuai.

/interface vlan print detail
/ip dhcp-server print detail
/ip dhcp-server network print
/ip dhcp-server lease print

Lanjut mengecek firewall

VLAN membagi jaringan, sedangkan akses antarsegmen tetap diatur oleh firewall MikroTik. Di konfigurasi saya ada rule untuk membatasi akses VLAN 30 ke layanan management seperti Cisco, Proxmox, dan Winbox. Untuk mengecek hasilnya, saya perlu melihat urutan rule, counter paket, lalu mencoba koneksi dari client.
