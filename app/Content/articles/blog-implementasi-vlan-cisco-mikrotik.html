Saya membagi home lab menjadi VLAN 10 untuk management, VLAN 20 untuk server, dan VLAN 30 untuk client. Pemisahan ini memberi setiap kelompok subnet serta gateway sendiri. MikroTik menyediakan interface VLAN dan DHCP, sedangkan Cisco SF200-24 mengatur keanggotaan port.

Satu uplink untuk tiga VLAN

ether4 MikroTik menjadi parent vlan10-management, vlan20-server, dan vlan30-client. Di sisi Cisco, GE1 membawa VLAN 10/20/30 sebagai tagged serta VLAN 1 sebagai untagged/PVID 1. Informasi ini lebih lengkap daripada hanya menyebut port sebagai trunk: kedua ujung harus sepakat tentang VLAN yang lewat dan perlakuan terhadap frame untagged.

Port akses menentukan segmen client

FE1 dan FE2 merupakan access port VLAN 10. FE3 menggunakan VLAN 30 dan, sesuai sketsa, menjadi cabang access point TP-Link. GE2 membawa VLAN 20 ke cabang server. FE4–FE24 terlihat memakai trunk/PVID 1; saya tidak menganggap semua port tersebut sudah membawa VLAN layanan.

DHCP yang konsisten dengan gateway

Pool tiap VLAN dimulai pada .100 dan berakhir .200. DHCP server bernama dhcp1, dhcp2, dan dhcp3 memakai lease 30 menit dan membagikan DNS 192.168.20.199. Untuk memeriksa masalah alamat, saya membandingkan interface VLAN, pool, scope network, dan lease, kemudian memastikan client memakai gateway segmennya sendiri.

/interface vlan print detail
/ip dhcp-server print detail
/ip dhcp-server network print
/ip dhcp-server lease print

Segmentasi belum sama dengan pembatasan akses

Setelah router dapat merutekan trafik antar-VLAN, kebijakan akses masih bergantung pada firewall. Backup saya memuat rule yang merujuk pembatasan VLAN 30 ke Cisco, Proxmox port 8006, dan Winbox. Keberadaan rule perlu dilengkapi pemeriksaan urutan, counter, dan pengujian dari client. Saya tidak menyebut seluruh VLAN terisolasi hanya berdasarkan tangkapan layar membership.

Dokumentasi VLAN, IP, dan DHCP memuat parameter serta cuplikan konfigurasi yang direkonstruksi dari backup saya.
