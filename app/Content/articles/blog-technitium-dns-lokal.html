Saya menjalankan Technitium DNS di 192.168.20.199 sebagai resolver lokal. Alamat DNS ini dibagikan ke client melalui DHCP MikroTik pada VLAN 10, 20, dan 30. Debian Web Server juga memakai resolver yang sama, jadi saya bisa menelusuri pengaturan DNS dari client sampai server.

Membagikan alamat DNS melalui DHCP

Pada scope DHCP, dns-server diisi 192.168.20.199. Pengaturan ini membuat client menerima DNS bersama alamat IP dan gateway. Saya tetap membedakannya dari pengaturan DNS pada router karena resolver yang dipakai MikroTik sendiri bisa berbeda dari resolver yang dibagikan ke client.

Ketika client memakai DNS yang berbeda, bagian pertama yang saya cek adalah pengaturan jaringan client dan lease DHCP. Mengubah konfigurasi Technitium tidak akan berpengaruh kalau query client ternyata dikirim ke resolver lain.

Mengecek DNS dari Debian

Di Debian, saya melihat nameserver melalui /etc/resolv.conf dan mencoba resolusi nama dengan getent. Domain azrilachdi.web.id mengarah ke 20.194.8.143. Alamat itu merupakan IP publik Azure VPS yang menjadi pintu masuk website saya.

cat /etc/resolv.conf
sudo dhcpcd -U ens18
getent ahostsv4 azrilachdi.web.id

Panel Technitium bisa saya akses melalui 192.168.20.199:5380, sedangkan layanan DNS memakai port 53. Di server Debian, /etc/resolv.conf dikelola oleh dhcpcd, sehingga perubahan manual pada file itu bisa tertimpa ketika lease diperbarui.

Kalau domain tidak bisa diakses

Saya mulai dengan memastikan client bisa menghubungi jaringan dan resolver. Setelah itu saya cek jawaban DNS. Kalau alamat domain sudah benar tetapi website tetap gagal dibuka, pengecekan berlanjut ke WireGuard, reverse proxy, dan container aplikasi.

Cara ini membantu saya mencari masalah di bagian yang tepat. DNS yang berhasil menjawab belum menjamin aplikasi berjalan, begitu juga aplikasi yang sehat belum menjamin client memakai DNS yang benar. Perintah dan alamat yang saya gunakan ada di catatan konfigurasi Technitium.
