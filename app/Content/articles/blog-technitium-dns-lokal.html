DNS lokal di home lab saya menggunakan Technitium pada 192.168.20.199. Alamat resolver ini muncul pada konfigurasi DHCP MikroTik dan /etc/resolv.conf Debian Web Server. Kecocokan kedua sisi membantu memastikan bahwa konfigurasi yang dibagikan router memang sampai ke client.

Mulai dari client

Saat nama domain tidak dapat dibuka, saya memeriksa apakah client mendapat IP, gateway, dan DNS yang sesuai. Debian berada pada 192.168.20.195/24 dengan gateway 192.168.20.1. File resolv.conf dibuat oleh dhcpcd, sehingga perubahan manual di file tersebut bisa hilang saat DHCP memperbarui lease.

cat /etc/resolv.conf
sudo dhcpcd -U ens18
getent ahostsv4 azrilachdi.web.id

Mengenali layanan yang sedang digunakan

Panel di 192.168.20.199:5380 menampilkan identitas Technitium DNS Server. Query UDP ke port 53 berhasil mengembalikan A record azrilachdi.web.id menuju 20.194.8.143. Hasil ini membuktikan resolver menjawab query tersebut saat diperiksa. Hasil itu tidak cukup untuk menyatakan bahwa saya memakai zona lokal, blocklist tertentu, atau transport DNS terenkripsi.

Menyebarkan DNS melalui scope DHCP

Scope VLAN 10, 20, dan 30 mengacu ke DNS yang sama. Konfigurasi resolver MikroTik sendiri terpisah dari DNS yang dibagikan melalui DHCP. Ketika sebuah perangkat memakai DNS berbeda, saya memeriksa pengaturan client dan lease sebelum mengubah Technitium.

Membedakan DNS dari masalah HTTP

Jika resolusi nama sudah benar tetapi website gagal, pemeriksaan berlanjut ke jalur Azure, WireGuard, reverse proxy, dan aplikasi. Mengganti DNS tidak akan menyelesaikan container yang tidak sehat. Sebaliknya, aplikasi yang sehat di loopback Debian belum membuktikan domain dapat diresolusikan oleh client.

Catatan operasional saya ada di dokumentasi Technitium. Detail zone, forwarder, cache, dan blocklist belum diekspor dari panel admin dan sengaja tidak diasumsikan dalam artikel ini.
