Saya memakai Azure VPS sebagai pintu masuk website dari internet. VPS ini terhubung ke home lab melalui WireGuard di MikroTik. Dari tunnel tersebut, request diteruskan ke Nginx Proxy Manager pada Debian Web Server, lalu ke aplikasi yang sesuai.

Tunnel antara Azure dan MikroTik

Interface WireGuard saya bernama wg-azure dengan alamat 10.10.0.2/24. Endpoint VPS berada di 20.194.8.143:51820, dengan peer tunnel 10.10.0.1 dan persistent keepalive 25 detik. Domain azrilachdi.web.id juga mengarah ke IP publik VPS tersebut.

HTTPS diterima oleh Nginx di Azure. Request kemudian berjalan melalui tunnel menuju layanan lokal. Saya mempertahankan informasi Host dan skema HTTPS pada proxy agar aplikasi membaca request pengunjung dengan benar.

Meneruskan trafik ke Debian

Pada konfigurasi firewall ada rule berkomentar VPS-NEXTCLOUD dengan sumber 10.10.0.1, tujuan 192.168.20.195, dan port TCP 80/443. Port tersebut dipakai untuk akses web ke Debian. Ada juga rule untuk membatasi akses VPS ke jaringan LAN lain.

Saat mengecek koneksi ini, saya melihat handshake, jumlah trafik RX/TX, route, dan counter firewall. Handshake membantu mengetahui apakah peer terhubung, sementara akses ke layanan tetap memerlukan route dan rule forwarding yang sesuai.

/interface wireguard peers print proplist=interface,current-endpoint-address,current-endpoint-port,last-handshake,rx,tx

Urutan pengecekan saat website gagal

Saya mulai dari jawaban DNS domain, kemudian status tunnel, route, dan akses HTTP di Debian. Kalau origin sudah merespons, saya lanjut ke proxy host dan log Nginx Proxy Manager. Setelah itu saya coba domain melalui HTTPS untuk mengecek jalur dari luar.

Akses pribadi dengan Tailscale

Selain WireGuard untuk jalur website, saya juga menggunakan Tailscale untuk akses VPN pribadi. Di sini saya fokus membahas koneksi Azure dan MikroTik yang meneruskan trafik web. Alamat tunnel serta perintah pengecekannya saya kumpulkan di dokumentasi VPN.
