Website portofolio saya dapat diakses melalui Azure VPS yang terhubung ke home lab menggunakan WireGuard. Dokumentasi deployment menjelaskan bahwa Nginx Azure mengakhiri HTTPS, kemudian trafik diteruskan melalui tunnel menuju Nginx Proxy Manager di Debian.

Parameter dari backup MikroTik

Interface tunnel bernama wg-azure dengan alamat 10.10.0.2/24. Backup memuat endpoint 20.194.8.143:51820 dan keepalive 25 detik. Rule firewall merujuk peer VPS 10.10.0.1. Saat diperiksa, DNS azrilachdi.web.id juga menghasilkan alamat publik 20.194.8.143.

Membatasi arti dari sebuah hasil pengujian

Backup memuat rule VPS-NEXTCLOUD menuju 192.168.20.195 pada TCP 80/443, serta rule berikutnya berkomentar VPS tidak boleh ke LAN lain. Nama rule tersebut mencerminkan konteks saat dibuat. Saya memakai nilai alamat dan port sebagai bukti konfigurasi, tanpa menganggap nama rule membuktikan status semua layanan saat ini.

Urutan diagnosis yang saya pakai

  1. Pastikan domain menghasilkan alamat publik yang benar.
  2. Periksa handshake, endpoint aktif, serta counter RX/TX WireGuard.
  3. Periksa route menuju layanan dan jalur baliknya.
  4. Uji HTTP pada Debian dan lihat log Nginx Proxy Manager.
  5. Bandingkan dengan akses domain melalui HTTPS.
/interface wireguard peers print proplist=interface,current-endpoint-address,current-endpoint-port,last-handshake,rx,tx

Posisi Tailscale dalam dokumentasi

Saya menyertakan Tailscale sebagai jalur akses VPN pribadi sesuai penggunaan home lab. Detail node, ACL, dan subnet route belum tersedia, dan tailscaled tidak aktif pada Debian Web Server yang diperiksa. Karena itu saya tidak menggambar Tailscale seolah-olah pasti terpasang di Debian atau Proxmox.

Artikel ini tidak memuat kunci WireGuard maupun konfigurasi rahasia. Dokumentasi VPN menjelaskan parameter yang sudah diketahui dan bagian yang perlu diperiksa pada perangkat sebelum melakukan perubahan.
