Routing dan firewall MikroTik

MikroTik menjadi gateway antarsegmen. Saya mengecek route dan counter firewall untuk melihat trafik yang diteruskan atau diblokir. Layanan management yang saya perhatikan antara lain Cisco 192.168.10.2, Proxmox 192.168.20.200:8006, dan Winbox 192.168.10.1:8291.

/ip route print
/ip firewall filter print stats
/ip firewall nat print stats
/ip service print

SSH, Docker, dan reverse proxy

ssh azril@192.168.20.195
cd /mnt/data/docker-compose/portfolio/repository
sudo docker compose --env-file ../runtime.env config --quiet
sudo docker compose --env-file ../runtime.env ps
sudo docker compose --env-file ../runtime.env logs --tail=50 app
curl --fail --header 'X-Forwarded-Proto: https' http://127.0.0.1:18081/ -o /dev/null
sudo systemctl status portfolio-deploy.timer --no-pager
sudo journalctl -u portfolio-deploy.service -n 50 --no-pager

Kalau origin di Debian merespons, saya lanjut mengecek proxy host portfolio-web:80 pada Nginx Proxy Manager. Kalau origin gagal, saya mulai dari status container, log aplikasi, dan koneksi database.

WireGuard dan akses dari luar

Untuk jalur Azure, saya mengecek interface wg-azure, peer 10.10.0.1, handshake, dan route. Setelah itu saya mencoba akses website dari domain publik. Tailscale saya gunakan untuk akses VPN pribadi.

Catatan sebelum mengubah konfigurasi

Saya menyimpan backup, mencatat bagian yang diubah, lalu mencoba kembali koneksinya. Untuk SSH, saya menjaga sesi lama sampai akses baru berhasil. Dengan cara ini saya masih punya jalan kembali kalau perubahan tidak berjalan sesuai rencana.

Catatan per bagian: VLAN dan DHCP, Technitium DNS, Debian dan SSH, Docker dan Nginx Proxy Manager, WireGuard dan VPN.
