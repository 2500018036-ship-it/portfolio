Server Debian bernama webserver menjalankan website portofolio dan layanan Docker. Pemeriksaan SSH dilakukan sebagai azril pada 192.168.20.195. Interface ens18 memiliki prefix /24, default route melalui 192.168.20.1, dan DNS 192.168.20.199.

Alamat server saat ini berasal dari DHCP

# /etc/network/interfaces
allow-hotplug ens18
iface ens18 inet dhcp

Lease aktif memiliki durasi 1800 detik dan DHCP server identifier 192.168.20.1. Sketsa awal menyebut IP statis melalui Winbox, tetapi sistem Debian saat audit memakai DHCP. Status reservasi lease pada router belum dibuktikan. Catatan ini mengikuti kondisi yang diamati, sehingga alamat server tidak disebut sebagai konfigurasi statis Debian.

ip -brief address show ens18
ip route
cat /etc/resolv.conf
sudo dhcpcd -U ens18
ping -c 3 192.168.20.1
getent ahostsv4 azrilachdi.web.id

Akses SSH dan pengaturan yang diamati

ssh azril@192.168.20.195
sudo sshd -T | grep -E "^(port|permitrootlogin|passwordauthentication|pubkeyauthentication) "

SSH mendengarkan pada port 22. Pengaturan efektif saat pemeriksaan menunjukkan pubkeyauthentication yes, passwordauthentication yes, dan permitrootlogin without-password. Nilai ini didokumentasikan sebagai keadaan server, bukan sebagai klaim bahwa semua praktik hardening telah diterapkan. Perubahan autentikasi harus mempertahankan sesi akses yang masih berfungsi dan diuji dari sesi kedua.

Layanan aplikasi

Container portfolio-app-1 menjalankan PHP 8.3 dan Apache. portfolio-db-1 menggunakan MariaDB 11.4. Port aplikasi dipetakan ke 127.0.0.1:18081, sedangkan database hanya berada pada network backend internal. Nginx Proxy Manager terhubung lewat web-proxy. Data database, unggahan, dan writable berada di luar image aplikasi.

Perintah operasi yang digunakan

cd /mnt/data/docker-compose/portfolio/repository
sudo docker compose --env-file ../runtime.env config --quiet
sudo docker compose --env-file ../runtime.env ps
sudo docker compose --env-file ../runtime.env logs --tail=50 app
curl --fail --header 'X-Forwarded-Proto: https' http://127.0.0.1:18081/ -o /dev/null
sudo systemctl status portfolio-deploy.timer --no-pager
sudo journalctl -u portfolio-deploy.service -n 50 --no-pager

Gunakan runtime.env yang sudah ada untuk menjalankan Compose. File tersebut menyimpan konfigurasi rahasia dan tidak dipublikasikan. Mulai diagnosis dari status container dan health check, lalu baca log Apache/aplikasi serta log deployment. Server juga menerima request monitoring ke /index.php/api/metrics yang menghasilkan 404; portofolio tidak memiliki endpoint tersebut dan request itu tidak membuktikan kegagalan halaman publik.
