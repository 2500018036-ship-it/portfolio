Debian Web Server saya bernama webserver dan memakai alamat 192.168.20.195/24 pada interface ens18. Gateway-nya 192.168.20.1 dan resolver DNS-nya 192.168.20.199. Server ini menjalankan portofolio serta Nginx Proxy Manager melalui Docker.

Konfigurasi jaringan Debian

Interface ens18 menggunakan DHCP. Bagian interface pada /etc/network/interfaces ditulis seperti berikut:

# /etc/network/interfaces
allow-hotplug ens18
iface ens18 inet dhcp

Lease yang diterima memiliki durasi 1800 detik atau 30 menit. Untuk melihat alamat, route, resolver, dan informasi lease, saya menggunakan perintah berikut sebelum mencoba koneksi ke gateway dan domain.

ip -brief address show ens18
ip route
cat /etc/resolv.conf
sudo dhcpcd -U ens18
ping -c 3 192.168.20.1
getent ahostsv4 azrilachdi.web.id

Mengakses server lewat SSH

ssh azril@192.168.20.195
sudo sshd -T | grep -E "^(port|permitrootlogin|passwordauthentication|pubkeyauthentication) "

SSH memakai port 22 dengan autentikasi password dan public key aktif. Pengaturan root adalah without-password. Kalau mengubah konfigurasi SSH, saya mempertahankan sesi yang masih terhubung dan mencoba akses dari sesi kedua sebelum menutupnya.

Container aplikasi dan database

portfolio-app-1 menjalankan PHP 8.3 dan Apache, sedangkan portfolio-db-1 memakai MariaDB 11.4. Aplikasi bisa dicek dari host melalui 127.0.0.1:18081. Database berada di network backend internal, sementara Nginx Proxy Manager terhubung ke aplikasi melalui network web-proxy.

Data database, unggahan, dan writable berada di /mnt/data/storage/portfolio, terpisah dari image aplikasi. Dengan begitu, pembaruan image tetap memakai data yang sudah ada.

Perintah untuk mengecek layanan

cd /mnt/data/docker-compose/portfolio/repository
sudo docker compose --env-file ../runtime.env config --quiet
sudo docker compose --env-file ../runtime.env ps
sudo docker compose --env-file ../runtime.env logs --tail=50 app
curl --fail --header 'X-Forwarded-Proto: https' http://127.0.0.1:18081/ -o /dev/null
sudo systemctl status portfolio-deploy.timer --no-pager
sudo journalctl -u portfolio-deploy.service -n 50 --no-pager

Saya memakai runtime.env yang sudah tersimpan di server untuk menjalankan Compose. Saat ada gangguan, saya mulai dari status container, health check, dan log aplikasi. Log deployment membantu mengecek proses build, migrasi, serta pergantian container.
