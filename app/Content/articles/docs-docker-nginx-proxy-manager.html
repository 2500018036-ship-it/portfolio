Portofolio ini memakai Docker Compose untuk menjalankan aplikasi CodeIgniter dan MariaDB. Nginx Proxy Manager meneruskan domain ke container aplikasi melalui alias portfolio-web pada port 80. Saya memakai network web-proxy untuk koneksi antara proxy dan aplikasi.

Port dan network pada Compose

Berikut bagian Compose yang mengatur port aplikasi dan network. Database memakai network backend internal, sedangkan port 127.0.0.1:18081 dipakai untuk mengecek aplikasi langsung dari Debian.

services:
  app:
    ports:
      - "127.0.0.1:${APP_PORT:-18081}:80"
    networks:
      backend:
      proxy:
        aliases:
          - portfolio-web
networks:
  backend:
    internal: true
  proxy:
    external: true
    name: ${PROXY_NETWORK:-web-proxy}

Database, unggahan, dan writable disimpan di /mnt/data/storage/portfolio. File pada volume tetap dipakai saat image baru dijalankan. Saya tidak memasukkan data produksi ke dalam image Docker.

Header HTTPS pada reverse proxy

TLS ditangani Nginx di Azure. Request kemudian melewati WireGuard dan Nginx Proxy Manager sebelum masuk ke aplikasi. Host dan X-Forwarded-Proto diteruskan agar aplikasi mengenali domain dan skema HTTPS yang dipakai pengunjung.

Nginx Proxy Manager memakai portfolio_original_scheme untuk meneruskan skema request asli. Karena cookie produksi menggunakan Secure, saya juga menyertakan header HTTPS saat mencoba origin dari Debian.

curl --fail --header 'X-Forwarded-Proto: https' http://127.0.0.1:18081/ -o /dev/null

Build dan deployment

Push ke main menjalankan GitHub Actions untuk validasi, build, migrasi database kosong, dan pengujian halaman. Timer Debian mengecek repository setiap dua menit dan memasang commit yang sudah lulus CI. Script deployment menyimpan snapshot database sebelum migrasi, lalu menunggu aplikasi sehat setelah container diganti.

cd /mnt/data/docker-compose/portfolio/repository
sudo docker compose --env-file ../runtime.env config --quiet
sudo docker compose --env-file ../runtime.env ps
sudo docker compose --env-file ../runtime.env logs --tail=50 app
curl --fail --header 'X-Forwarded-Proto: https' http://127.0.0.1:18081/ -o /dev/null
sudo systemctl status portfolio-deploy.timer --no-pager
sudo journalctl -u portfolio-deploy.service -n 50 --no-pager

Mengecek origin sebelum domain

Kalau origin gagal, saya membaca log aplikasi dan mengecek koneksi database. Kalau origin merespons tetapi domain gagal, saya lanjut ke Nginx Proxy Manager, WireGuard, DNS, dan TLS. Pengecekan bertahap ini membantu saya menemukan bagian yang bermasalah tanpa langsung mengubah semua layanan.
