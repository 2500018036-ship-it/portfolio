Saya memakai Technitium DNS di 192.168.20.199 sebagai resolver home lab. Layanan DNS menerima query pada port 53, sedangkan panel pengelolaannya bisa dibuka melalui 192.168.20.199:5380. Debian Web Server dan client DHCP diarahkan ke alamat DNS ini.

DNS pada DHCP MikroTik

Scope 192.168.10.0/24, 192.168.20.0/24, dan 192.168.30.0/24 memakai dns-server=192.168.20.199. Client menerima alamat tersebut bersama IP dan gateway dari MikroTik. Saya mengeceknya dengan perintah berikut:

/ip dhcp-server network print detail
# Ketiga scope VLAN memakai dns-server=192.168.20.199

Pengaturan ini adalah DNS yang dibagikan ke client. Pengaturan resolver pada MikroTik sendiri berada di bagian terpisah, sehingga saya mengecek keduanya sesuai perangkat yang sedang mengalami masalah.

Resolver pada Debian

Di Debian, /etc/resolv.conf berisi nameserver 192.168.20.199 dan dikelola oleh dhcpcd. Saya melihat isi file tersebut, membaca lease, lalu mencoba resolusi domain. Untuk azrilachdi.web.id, jawaban A record mengarah ke 20.194.8.143, yaitu IP publik Azure VPS saya.

cat /etc/resolv.conf
# nameserver 192.168.20.199
sudo dhcpcd -U ens18
getent ahostsv4 azrilachdi.web.id

Saya menghindari perubahan manual pada /etc/resolv.conf karena file ini bisa diperbarui kembali saat lease DHCP berubah. Kalau alamat resolver tidak sesuai, saya mulai dari scope DHCP dan pengaturan jaringan client.

Saat resolusi nama bermasalah

Saya cek konektivitas client ke jaringan, lalu akses ke 192.168.20.199 dan jawaban DNS-nya. Setelah nama domain menghasilkan alamat yang benar, saya lanjut menguji layanan web. Dengan urutan ini, masalah DNS dan masalah aplikasi lebih mudah dibedakan.

Untuk alur layanan web dari internet sampai Debian, saya menyimpan perintah pengecekannya di dokumentasi WireGuard dan Azure.
