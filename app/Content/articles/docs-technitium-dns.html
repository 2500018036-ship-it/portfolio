Technitium DNS menjadi resolver lokal pada home lab saya. Debian Web Server di 192.168.20.195 menggunakan 192.168.20.199 sebagai nameserver. Identitas layanan dikonfirmasi melalui halaman Technitium DNS Server di port 5380, sementara query UDP ke port 53 menghasilkan jawaban DNS.

Alur resolusi nama

Client menerima alamat DNS melalui DHCP MikroTik. Query dikirim ke 192.168.20.199, lalu jawaban dikembalikan ke client. Saat pemeriksaan, azrilachdi.web.id menghasilkan A record 20.194.8.143. Ini adalah hasil resolusi yang diamati, bukan bukti bahwa sebuah zona lokal atau split DNS tertentu sudah dikonfigurasi.

DNS yang dibagikan MikroTik

/ip dhcp-server network print detail
# Ketiga scope VLAN memakai dns-server=192.168.20.199

Nilai ini terdapat pada scope 192.168.10.0/24, 192.168.20.0/24, dan 192.168.30.0/24. Router memiliki pengaturan resolver sendiri; jangan menyamakan resolver router dengan DNS yang dibagikan ke client.

Memeriksa client Debian

cat /etc/resolv.conf
# nameserver 192.168.20.199
sudo dhcpcd -U ens18
getent ahostsv4 azrilachdi.web.id

/etc/resolv.conf di server dibuat oleh dhcpcd. Mengeditnya secara manual dapat tertimpa saat lease diperbarui. Jika DNS client berubah, periksa scope DHCP dan lease terlebih dahulu.

Batas informasi yang sudah diperiksa

Zone, forwarder, blocklist, DNS-over-HTTPS, dan pengaturan cache di panel admin Technitium belum diekspor. Dokumentasi ini tidak mengklaim fitur tersebut sudah dipakai. Saat client gagal melakukan resolusi, bedakan gangguan koneksi ke resolver, kesalahan nama domain, dan masalah upstream. Uji konektivitas IP terlebih dahulu, lalu bandingkan hasil query dari client dan server.
