Jalur publik website melewati Azure VPS, WireGuard, dan home lab. Backup MikroTik memuat interface wg-azure, alamat tunnel 10.10.0.2/24, endpoint peer 20.194.8.143:51820, dan persistent keepalive 25 detik. Aturan firewall pada backup merujuk peer VPS 10.10.0.1. DNS domain portofolio juga mengarah ke 20.194.8.143 saat diperiksa.

Kunci privat, public key peer, token, dan isi backup biner tidak disertakan dalam website. Cuplikan di bawah digunakan untuk memeriksa status pada perangkat yang sudah dikonfigurasi, bukan untuk membuat peer baru.

/interface wireguard print
/ip address print where interface=wg-azure
/interface wireguard peers print proplist=interface,current-endpoint-address,current-endpoint-port,last-handshake,rx,tx

Routing dan batas akses

Backup memuat aturan berkomentar VPS-NEXTCLOUD dengan sumber 10.10.0.1, tujuan 192.168.20.195, dan port TCP 80/443, diikuti aturan berkomentar VPS tidak boleh ke LAN lain. Dokumentasi deployment portofolio menetapkan alur yang sama menuju Nginx Proxy Manager. Keberadaan aturan dalam backup tidak menggantikan pemeriksaan counter, urutan rule, AllowedIPs, dan route aktif pada router saat ini.

Akses Tailscale

Saya juga menggunakan Tailscale untuk akses VPN pribadi. Namun node, alamat tailnet, ACL, subnet router, dan exit node belum tersedia untuk diperiksa. Layanan tailscaled tidak aktif pada Debian Web Server ketika audit dilakukan. Karena itu diagram menampilkan Tailscale sebagai jalur akses logis terpisah, tanpa mengaitkannya secara pasti ke Debian atau mengklaim ada subnet route aktif.

Pemeriksaan saat akses luar gagal

  1. Pastikan DNS domain mengarah ke endpoint publik yang benar.
  2. Periksa handshake dan trafik tunnel pada perangkat WireGuard.
  3. Uji layanan Debian dari sisi LAN, lalu cek akses melalui tunnel.
  4. Periksa jalur balik, rule forwarding, dan log reverse proxy.
  5. Untuk Tailscale, periksa node dan kebijakan akses pada instalasi yang benar sebelum menyimpulkan layanan LAN bermasalah.

Konfigurasi Nginx Azure tidak tersedia langsung dalam audit ini. Alur terminasi TLS di Azure bersumber dari dokumentasi deployment yang sudah ada; pengujian domain publik memverifikasi hasil akses website, bukan seluruh konfigurasi VPS.
